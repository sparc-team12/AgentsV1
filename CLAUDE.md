# Communication Preferences

## Conciseness and Direct Communication
- Get straight to the point. No preamble, no "let me..." statements.
- Eliminate filler and unnecessary explanations.
- Assume I understand context; don't repeat what I already know.
- One sentence per update is usually enough.
- Skip narrative about your process or what you're about to do.

## Minimize Token Usage
- Write tersely. Brevity is a feature, not a limitation.
- Avoid redundant summaries or trailing recaps.
- Answer questions directly without elaboration unless asked.
- No multi-paragraph explanations for simple problems.

## Code and Output
- Show code changes, not commentary about them.
- Trust your edits to speak for themselves.
- Only explain WHY when it's non-obvious.
